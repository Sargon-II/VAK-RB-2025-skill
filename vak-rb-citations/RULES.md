# Оформление библиографии по правилам ВАК РБ (редакция от 13.10.2025, приказ № 206)

Это ядро инструмента для форматирования библиографических описаний. Файл написан так, чтобы им мог руководствоваться любой ИИ-агент с доступом к чтению файлов, веб-поиску и (опционально) выполнению команд — не только Claude Code. Работает вместе с [`vak_rb_2025_examples.json`](vak_rb_2025_examples.json) — базой из ~120 официальных образцов ВАК РБ, сгруппированных по ~50 категориям источников.

## Когда использовать

Пользователь даёт один из вариантов:
- **Список литературы целиком** (например, раздел «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» из статьи/диссертации) — с записями в произвольном/неполном виде, вперемешку с уже оформленными.
- **Одну ссылку** — пару строк описания источника или просто «сырые» данные (автор, название, издательство и т.п. в любом порядке).

Задача: (1) определить тип источника, (2) оформить его строго по образцу ВАК РБ 2025, (3) НЕ придумывать данные, которых нет.

## Пошаговый алгоритм

### Шаг 1 — Разбор входных данных
Извлеките из данной пользователем строки/абзаца всё, что уже известно: автор(ы), название, подзаголовок, издательство, город, год, страницы, том, номер журнала, DOI, URL, дата обращения, тип документа (диссертация/статья/сайт и т.д.), язык оригинала.

### Шаг 2 — Классификация типа источника
Определите категорию по дереву решений (в порядке проверки):

1. Это законодательный/нормативный акт, международный договор, конституция, послание главы государства, ГОСТ/СТБ, патент? → раздел 3 JSON (`официальные документы`) либо соответствующие категории раздела 1 (`tech-regulations`, `standards`, `patents` и т.п.).
2. Это часть большего документа — статья в журнале/сборнике/газете, глава книги, запись в энциклопедии, рецензия? → раздел 2 JSON (`составные части документов`). Ключевой признак — в описании будет разделитель « // » между названием части и названием контейнера.
3. Иначе — это самостоятельный документ целиком (книга, диссертация, автореферат, отчёт о НИР, сайт, CD и т.п.) → раздел 1 JSON.
   - Внутри раздела 1 определите подкатегорию по числу и типу авторов, наличию тома/серии, виду носителя (бумага/CD/сайт/карта/ноты и т.д.) — см. `notes` в каждой категории JSON.

Если не уверены между двумя категориями — берите ту, чей набор полей ближе всего к тому, что реально есть у источника (не усложняйте: если у источника нет конференции/серии/электронного адреса — не добавляйте соответствующую область).

### Шаг 3 — Найти ближайший образец и скопировать его структуру
Откройте в `vak_rb_2025_examples.json` найденную категорию и возьмите её `examples` как эталон пунктуации:
- Разделители областей описания: « – » (тире с пробелами с обеих сторон, НЕ дефис).
- « / » отделяет область ответственности (авторы/редакторы) от заглавия.
- « // » — отделяет часть от контейнера (только для составных частей, раздел 2).
- « ; » — отделяет друг от друга несколько групп ответственности (например, авторов от организации, или редактора от составителя).
- « : » — отделяет подзаголовок, сведения об издании/типе документа, место от издательства.
- Сокращения городов: Мн. (Минск), М. (Москва), СПб. (Санкт-Петербург) и т.д. — сохраняйте написание, принятое в образцах.
- Правило числа авторов в заголовке описания: 1–3 автора → запись начинается с «Фамилия, И. О. Название»; 4 и более → запись начинается сразу с названия, а все авторы перечисляются только после « / ». При этом: ровно 4 автора — перечисляются все 4; 5 и более — первые 3 + «[и др.]» (или «[et al.]» для нерусскоязычных источников).
- Диссертация — объём в листах «N л.»; автореферат — в страницах «N с.». Не перепутать.
- Электронный ресурс — обязательно закрывающая формула «– URL: <ссылка> (дата обращения: DD.MM.YYYY).» (использовать реальную дату, когда ссылка была фактически проверена агентом, а не дату из образца).
- Для составных частей (раздел 2): у книги-контейнера после «//» издательство, как правило, ОПУСКАЕТСЯ — остаются только место и год.

### Шаг 4 — Заполнение недостающих данных (ключевое место, где раньше были ошибки)

**Правило №1: никогда не придумывать число страниц, год, издательство или другие фактические данные.** Если поле неизвестно — его нужно либо найти, либо явно пометить как непроверенное. Галлюцинация здесь хуже, чем явный пробел.

Порядок поиска недостающих данных:
1. **Локальные материалы проекта.** Если источник — один из уже оцифрованных документов (например, PDF или DOCX файлы в рабочей директории проекта), искать данные там: реальное число страниц PDF, точное название главы/раздела, выходные данные и т. п.
2. **Веб-поиск.** Если данных нет локально — пользователь разрешил веб-поиск. Порядок приоритета источников для проверки библиографических фактов:
   - WorldCat (worldcat.org) — число страниц, ISBN, издательство, год для книг.
   - Сайт/каталог самого издательства.
   - Национальные и университетские библиотечные каталоги (напр. Национальная библиотека Беларуси, РГБ, Google Books — «продолжение» описания часто содержит точное число страниц).
   - Для журнальных статей — сайт журнала/издателя (DOI → crossref/страница издателя) для точных номеров страниц, тома, выпуска.
   - Для официальных актов и НПА — pravo.by, ЭТАЛОН/КонсультантПлюс/ilex (не путать с бесплатным доступом — для этих баз в описании даты не даётся URL, а даётся только «дата обращения»).
3. **Если после поиска данные всё равно не найдены** — оставить поле явно помеченным, например: `[СТРАНИЦЫ НЕ НАЙДЕНЫ — проверить вручную]` или `[ГОД НЕ УКАЗАН В ИСТОЧНИКЕ]`. Не удалять пометку молча и не заменять её правдоподобной на вид цифрой.
4. Когда значение всё же найдено через веб-поиск, а не было в исходных данных пользователя — желательно зафиксировать это (например, в комментарии рядом или в сводке по итогам обработки списка), чтобы пользователь мог сам перепроверить одно-два наиболее сомнительных места, а не весь список.

### Шаг 5 — Собрать итоговую строку
Соберите запись строго по структуре найденного образца, подставив реальные данные источника. Сверьте пунктуацию посимвольно с образцом той же категории (тире, пробелы вокруг тире, точки после сокращений).

### Шаг 6 — Финальная проверка перед выдачей результата
- Все ли поля на месте и в правильном порядке?
- Нет ли придуманных (неподтверждённых) числовых данных без пометки?
- Единообразны ли сокращения по всему списку (не «М.» в одном месте и «Москва» в другом)?
- Если обрабатывался список целиком — сохранена ли исходная нумерация или пользователь просил новую?

## Формат вывода при пакетной обработке списка
На входе — весь раздел списка источников (может быть неполным/черновым). На выходе:
1. Список того же объёма, полностью переоформленный по ВАК РБ 2025, с сохранением порядка/нумерации, если не оговорено иное.
2. Отдельно, после списка — краткая сводка: какие записи потребовали веб-поиска для дозаполнения (с указанием, что именно было найдено и где), и какие поля остались непроверенными/непомеченными флагом (если такие есть) — чтобы пользователь мог сам перепроверить самые рискованные места, а не весь список целиком.

## Иноязычные источники: на каком языке описывать и когда переводить

Единственный образец ВАК РБ с нелатинским/некириллическим языком — китайская статья «Сюн Доуинь»: она даётся как **полное параллельное описание**: сначала вся библиографическая запись целиком на языке оригинала (автор, название, контейнер, том/номер, страницы), затем « = », затем вся запись ещё раз целиком в переводе (тот же том/страницы). Это НЕ «перевод + оригинал в скобках» — так делать неправильно, это не встречается ни в одном официальном образце.

При этом чисто иноязычные источники без предоставленного переводчиком перевода (Albrow, Karutz, Rappuoli и т.п.) даются в списке ВАК РБ **только на языке оригинала**, без всякой русской версии — ровно как напечатано у источника.

Из этого следуют два законных варианта на выбор пользователя:
1. **Только язык оригинала** — если переводить не нужно/не хочется тратить место, описывать источник полностью на его родном языке (структурные разделители « – », « / », « // », « : », « ; » остаются теми же символами независимо от языка описания; для незнакомых с языком-источником оформителю разрешено использовать интернациональные пометки тома/страниц вида «Vol. N», «P. X–Y», как это сделано в самом образце Сюн Доуиня даже внутри китаеязычной части).
2. **Параллельное описание** «оригинал = перевод» — только если нужно дать русский текст для читателя статьи; тогда обе части идентичны по факту (том, страницы), меняется только текст на естественном языке.

**Важно:** язык описания привязан к тому изданию, которое реально держит в руках/проверял исследователь. Нельзя писать издание на одном языке (например «Пекин: Издательство литературы на иностранных языках» — это реальное официальное русскоязычное издание Foreign Languages Press), а номера страниц брать из другого, физически иного издания (например, из китайского оригинала) — у разных изданий (даже одного и того же произведения, даже одного и того же издательства) страницы почти никогда не совпадают. Если верифицированы только страницы китайского PDF — описывать источник нужно как китайское издание, а не выдавать его за русское.

## Ограниченное число источников: регистрировать книгу, а не каждую цитату из неё

Если у публикации есть жёсткий лимит на число позиций в списке литературы, а нужно опереться на много отдельных фрагментов (речей/статей/глав) из одного и того же (много)томного издания — **не** заводи отдельную позицию списка на каждый фрагмент («составная часть», раздел 2 JSON). Вместо этого:

1. Зарегистрируй как источник САМУ КНИГУ/ТОМ целиком (раздел 1 JSON, обычная монография одного автора: автор, название, место : издательство, год, объём — реальное число страниц издания).
2. В тексте статьи цитируй сколько угодно разных фрагментов этой книги через `[номер источника, с. N]`, каждый раз с нужной конкретной страницей — это не создаёт новых позиций списка, лимит не расходуется.
3. Если работа состоит из нескольких физически разных томов (например, многотомное издание или собрание сочинений с разными ISBN/годами), каждый ИСПОЛЬЗУЕМЫЙ том — это своя, отдельная позиция списка (это разные книги), а НЕ отдельная позиция на каждую речь/статью внутри тома. Число задействованных томов и есть то, что должно совпадать с лимитом источников — а не число процитированных фрагментов внутри них.

Ошибка, которую это правило предотвращает: заведение нескольких разных позиций списка на несколько глав/речей, которые физически лежат в одном и том же томе — это впустую тратит лимит (де-факто это один и тот же источник, процитированный трижды).

## Известные ограничения
- Правила описывают именно раздел «Список использованных источников» диссертаций/авторефератов ВАК РБ. Другие требования (объём диссертации, порядок оформления титульного листа и т.п.) в этот файл не входят.
- Если в реальном источнике встретится тип, для которого нет прямого образца в JSON — нужно скомбинировать ближайшие по смыслу категории (например, «статья + официальный документ»), сохраняя общую логику областей описания и разделителей, а не изобретать новую пунктуацию.
